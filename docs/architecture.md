# Architecture

Broski is one Swift package with a shared core, a Mac app, and an iPhone app generated by XcodeGen. The logic lives in `Sources/BroskiCore`, so the Mac app, the iPhone app and the MCP server stay thin and the logic is tested once.

## Targets

| Target | What it is |
|---|---|
| `BroskiCore` | All the logic, no UI: the model gateway and providers, the conversation, memory, recall, notes, trackers, onboarding, the vault and every stored format. Shared with the iPhone app. |
| `Broski` | The Mac menu-bar app (SwiftUI and AppKit). The same executable is the MCP server (`--mcp`) and the developer tools (`--snapshot`, `--chat-check`, `--diagnose`, `--check-folder`). |
| `BroskiBark` | On-device English speech recognition: Bark 3.0 on Core ML (audio front end, encoder, TDT decoder). Shared with the iPhone app. |
| `BroskiWhisper` | whisper.cpp (Metal) behind a small Swift API. The prebuilt XCFramework is pinned by checksum in `Package.swift`. |
| `BroskiCoreTests` | Unit tests (Swift Testing). New code is written test-first here. |
| `BroskiSelfTest` | Older assertion checks (`swift run BroskiSelfTest`); they move into the unit tests as modules change. |
| `BarkCheck`, `WhisperCheck` | Command-line tools that transcribe audio files through each engine. |
| `iOS/` | The iPhone app (`BroskiPhone`) and its Control Center buttons (`BroskiWidgets`), described in `iOS/project.yml`. |
| `site/` | The website, published to GitHub Pages by `.github/workflows/pages.yml`. |

## The model gateway

Every call to a model goes through `ModelGateway`. No feature talks to a provider directly.

1. **A feature asks for a role:** fast, everyday or deep. It never names a provider.
2. **The router picks the model** (`ModelRouter`): privacy first (a local-only conversation may use only models on this device, and is refused before anything is sent when there's none), then what the model must read (images need a model that reads images; PDFs go as text to one that can't), then the day's budget (past the daily limit, work moves one role down).
3. **The gateway masks secrets** in the text (`SecretMask`), sends through a connector, and logs the call's tokens, cost and task to the usage log.
4. **Connectors** speak each wire format: `AnthropicConnector` (the Messages API), `OpenAICompatibleConnector` (chat completions: OpenAI, Gemini, OpenRouter, Groq, Mistral, DeepSeek, Ollama, LM Studio, any compatible server), and `AppleOnDeviceConnector` (Foundation Models, macOS 26 and iOS 26).
5. **Presets** (`ProviderPreset`) say what each provider needs, what it can read, whether it can hold a reply to a JSON schema, and which model it suggests for each role. Providers that can't hold a schema get it in their instructions, and replies are read leniently.

Code checks capabilities (images, PDFs, structured output), never a provider's name. Tests swap in a fake connector, so no test touches the network or spends money.

## Stored formats

Everything Broski stores is a plain file in your Broski folder. Newer formats carry a version (`"v": 1` in JSON and JSONL, `format: 1` in front matter), with round-trip and upgrade tests. Readers skip lines they can't parse instead of failing the whole file.

| File | Format | Version |
|---|---|---|
| `inbox/*.md`, `projects/<p>/*.md` | A note: markdown with a front-matter header | No version field; another editor's front-matter lines are kept byte for byte |
| `projects/<p>/sessions/<id>/` | `session.md`, `shots/`, `report.md` | No version field |
| `projects/<p>/PROJECT.md` | The living page | No version field |
| `conversations/<month>/<day>.<device>.jsonl` | One turn per line | `"v": 1` |
| `memory/about-you.md` | What Broski knows about you, yours to edit | Plain markdown |
| `memory/remembered.<device>.jsonl` | Remember and forget events | `"v": 1` |
| `memory/riff-rules.<device>.jsonl` | Riff rules added and dropped | `"v": 1` |
| `memory/reflection.mac.json` | How far reflection has read | `"v": 1` |
| `projects/<p>/decisions.<device>.jsonl` | Decisions with dates, each able to replace an older one | `"v": 1` |
| `projects/<p>/resources/` | Files you shared; `links.<device>.jsonl`; saved web pages | `"v": 1`; pages `format: 1` |
| `usage/<month>.<device>.jsonl` | One line per model call: role, provider, model, task, tokens, cost | `"v": 1` |
| `packs/<id>.json` | Your own packs | `"v": 1` |
| `projects/<p>/setup/command-center.json` | A project's widgets | `"v": 1` |
| `automations.json` | Automation rules | `"v": 1` |
| `vault/vault.json`, `vault/items/<id>.vault` | The vault's wrapped key, and one sealed file per note | `"format": 1` (inside the encryption for notes) |
| `config.json` | Settings, model choices, local-only projects | No version field; every key is optional and falls back to its default |
| `projects.json` | Every project's name, folders, trackers and earlier names | No version field |
| `trackers/<id>.broski.json`, `trackers/state/` | Tracker manifests and last-read state | No version field |
| `projects/<p>/stream.jsonl` | The change stream | No version field |

`config.json` is read with care: one bad value falls back on its own, a malformed local-only list fails closed, and a file that won't parse is kept as `config.broken.json` while every project counts as local only.

## One writer per file

Two devices writing one file is how sync loses data, so each device appends to its own files: `<day>.mac.jsonl` and `<day>.iphone.jsonl`, `remembered.mac.jsonl` and `remembered.iphone.jsonl`, and so on. Readers merge every device's files in time order. Times keep fractional seconds, so a forget written in the same second as its remember still sorts after it.

Files with one owner:

- `config.json`, `PROJECT.md`, `automations.json`, reflection's state and the automations cursor are written by the Mac. The iPhone only reads them.
- A note is one markdown file either device may edit. Broski re-reads it from disk before changing it, so the other device's edit survives.

One exception today: a project's change stream (`projects/<p>/stream.jsonl`) is a single file that the Mac's tracker reads and a decision saved on either device both append to.

## Sync through iCloud

Broski has no server. To share notes between the Mac and the iPhone, the Broski folder moves into iCloud Drive (Settings › General › Sync with iPhone) and the iPhone opens the same folder. iCloud moves the files; Broski only ever reads and writes them.

- iCloud keeps a file it hasn't downloaded as a hidden `.name.icloud` placeholder. Broski asks for it and never writes defaults over it: a `config.json` still downloading means every project is local only until it arrives.
- The Mac watches the folder and refreshes the open conversation when the iPhone's turns arrive; the iPhone checks a cheap fingerprint of the conversation files every 4 seconds while Talk is on screen.
- The vault syncs as ciphertext. Keys never sync.

## Roadmap

- **Low-power wake word.** A [sherpa-onnx keyword spotter](https://github.com/k2-fsa/sherpa-onnx) in front of the recognizer, so the wake word costs almost nothing.
- **Better transcription.** macOS 26 `SpeechAnalyzer`, once built with that SDK, or [FluidAudio](https://github.com/FluidInference/FluidAudio) Parakeet for accuracy.
- **Splitting rambles.** Filing already tidies the wording and picks the project; next, split a long ramble into several notes.
- **Claude Code hand-off.** Today the Tracker tab copies a prompt for the thread that owns a record; next, send it straight to that session.
- **Auto-update** (Sparkle) once there's a signed release channel.

## Prior art

OpenClaw's macOS voice wake (MIT) inspired the on-device recognizer, the text-gate design, and restarting the recognizer after each capture. VoiceInk and FluidVoice (GPL) informed the floating-panel UX; they were studied, and no code was copied.
